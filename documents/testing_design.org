* 1. はじめに

本ドキュメントは、Rust 製 GUI テキストエディタ（wgpu + cosmic-text ベース）における
テスト戦略の設計・方針・将来計画をまとめたものである。
アーキテクチャ設計書（[[file:architecture_design.org][architecture_design.org]]）と対になるドキュメントとして位置づける。

** 1.1. 基本方針

GPUレンダリングを伴うプロジェクトのテストは、「描画テストをしない」のではなく、
「ロジックが安定してから段階的に追加する」のが標準的なプラクティスである。

現段階では純粋ロジックの単体テストを最優先とし、描画テストはマイルストーンに応じて
後から追加する方針とする。

* 2. テスト可能性に基づくレイヤ分類

アーキテクチャの3レイヤ（§2 参照）は、テストしやすさの観点から以下のように分類される。

#+BEGIN_SRC plaintext
【テストしやすさ】    【レイヤ】                  【テスト戦略】
──────────────────────────────────────────────────────────────────
 High │ editor/        (純粋ロジック)    → 単体テスト（インライン #[cfg(test)]）
      │ 座標変換ロジック (純粋関数)       → 単体テスト（関数として切り出し）
      │ イベント→状態遷移               → 統合テスト（tests/ ディレクトリ）
 Low  │ renderer/      (GPU依存)        → 描画ロジックのみ単体、GPU部はスキップ
──────────────────────────────────────────────────────────────────
#+END_SRC

* 3. テストレベルの定義

描画テストには3つのレベルを定義する。
本プロジェクトでは現フェーズはレベル1のみ導入し、段階的にレベル2・3へ移行する。

** 3.1. レベル1：ロジックテスト（GPU不要）― 今すぐ導入

- GPU・ウィンドウを一切使用しない純粋な関数・状態のテスト。
- ~cargo test~ で常時実行可能。CI の ~just ci~ にそのまま組み込める。
- 対象：カーソル位置計算、バッファ操作、座標変換の数値確認。

** 3.2. レベル2：スナップショットテスト（ソフトウェアレンダラ使用）― cosmic-text 導入後に検討

- wgpu の ~Backends::GL~ (Mesa softpipe / llvmpipe) でヘッドレス実行。
- フレームバッファを CPU 側に readback し、PNG として保存してピクセル比較。
- CI では Docker + llvmpipe が必要（GitHub Actions で対応可能）。
- 追加コスト：~Cargo.toml~ に ~[features] headless-test = []~ を追加し、
  CI YAML に ~apt-get install libegl-dev mesa-utils~ 相当を追加するだけ。
- 価値が出るタイミング：~cosmic-text~ でテキストレイアウトを行い、
  「特定のフォントで特定の文字が正しいピクセル位置に描画されるか」を確認したい段階。

** 3.3. レベル3：ゴールデンイメージテスト（参照画像比較）― 将来的な検討

- 期待画像（~.png~）をリポジトリに保存し、レンダリング結果との差分をピクセル単位で比較。
- フォントレンダリングの差異でフォールスアラートが出やすいため、
  許容ピクセル差分（tolerance）の設定が必要。
- 採用タイミング：UI の見た目の回帰テストが必要になった段階。

** 3.4. 業界での実例

| プロジェクト  | 描画テストの方針                                                                                 |
|---------------+--------------------------------------------------------------------------------------------------|
| wgpu 本体     | ~wgpu-test~ クレートを持ち、ヘッドレス GPU でピクセル比較テストを実施                           |
| Zed           | ~GPUI~ に ~TestAppContext~ という描画なしのダミーコンテキストを用意し、UI ロジックのみテスト     |
| Bevy          | ECS ロジックは通常テスト。レンダリングパイプラインは ~headless~ フィーチャーフラグで分離         |
| cosmic-text   | テキストレイアウト計算の結果（グリフの XY 座標・幅）をピクセル値として数値アサート。GPU 描画なし |

* 4. 現フェーズ（マイルストーン1）のテスト実装計画

** 4.1. dev-dependencies の追加

~Cargo.toml~ に ~[dev-dependencies]~ ブロックを新設し、以下を追加する。

#+BEGIN_SRC toml
[dev-dependencies]
# Property-based testing: automatically explores boundary values
proptest = "1"
#+END_SRC

~proptest~ を採用する理由：カーソル位置（~usize~）の境界値（0、~usize::MAX~ 付近、
大きい任意値）のテストは手書きよりも自動生成の方が抜け漏れが少ない。

** 4.2. editor/cursor.rs への単体テスト追加

*設計方針：* ~app.rs~ に直書きされているキー操作ロジック（~saturating_add/sub~）を
~Cursor~ のメソッドとして引き上げることで、~winit~ に依存せずテスト可能にする。

追加するメソッド：

#+BEGIN_SRC rust
impl Cursor {
    /// Moves the cursor one position to the right.
    pub fn move_right(&mut self) {
        self.position = self.position.saturating_add(1);
    }

    /// Moves the cursor one position to the left (minimum: 0).
    pub fn move_left(&mut self) {
        self.position = self.position.saturating_sub(1);
    }
}
#+END_SRC

テストケース（~#[cfg(test)]~ ブロックにインライン記述）：

| テストケース                                 | 確認内容                                             |
|----------------------------------------------+------------------------------------------------------|
| ~move_right~ 基本動作                        | position = 0 → move_right → position = 1            |
| ~move_left~ アンダーフロー保護               | position = 0 → move_left → position = 0（panic なし） |
| ~move_right~ を N 回                         | position = 0 → move_right × N → position = N        |
| ~move_left/right~ の往復                     | 任意の position で move_left → move_right が恒等     |
| ~usize::MAX~ 付近での ~move_right~           | saturating_add により panic しない（proptest）       |
| 任意の position で ~move_left~ を繰り返す   | 最終的に 0 に収束し panic しない（proptest）         |

** 4.3. renderer/ の座標変換を純粋関数として切り出し

現在 ~renderer/mod.rs~ に定数として散在している座標計算を純粋関数に切り出す。
これにより ~wgpu~ を一切使わずにテスト可能になる。

切り出す関数（~renderer/mod.rs~ または ~renderer/coords.rs~ 新設）：

#+BEGIN_SRC rust
/// Calculates the pixel X coordinate of the cursor.
///
/// # Arguments
/// - `position`   – byte offset in the text buffer
/// - `char_width` – pixel width per character position (placeholder: 10.0)
/// - `margin_x`   – left margin in pixels (placeholder: 8.0)
pub fn cursor_pixel_x(position: usize, char_width: f32, margin_x: f32) -> f32 {
    position as f32 * char_width + margin_x
}
#+END_SRC

テストケース：

| テストケース            | 確認内容                            |
|-------------------------+-------------------------------------|
| position = 0            | x = margin_x (= 8.0)                |
| position = 1            | x = char_width + margin_x (= 18.0) |
| position = 10           | x = 108.0                           |
| proptest: 任意 position | x は常に margin_x 以上              |

** 4.4. tests/editor_integration.rs 新設

~App~ 構造体は ~winit~ に強く結合しているため、~editor~ レイヤの状態遷移を
~App~ なしで直接テストする統合テストを用意する。

#+BEGIN_SRC plaintext
tests/
└── editor_integration.rs   # editor::cursor + (将来) editor::buffer を組み合わせたシナリオテスト
#+END_SRC

テストシナリオ：

| シナリオ                         | 確認内容                                              |
|----------------------------------+-------------------------------------------------------|
| 右移動 × 10                      | position == 10                                        |
| 右移動後に左移動を 11 回         | position == 0（アンダーフロー保護）                   |
| （buffer 追加後）テキスト挿入    | カーソル位置がバッファ長を超えない                    |
| （buffer 追加後）先頭で左移動    | position = 0 を維持しバッファ破損なし                 |

* 5. 将来マイルストーンのテスト設計

** 5.1. editor/buffer.rs 新設時（ropey 追加）

~buffer.rs~ 内に ~#[cfg(test)]~ ブロックとして追加するテストケース：

| テストケース                    | 確認内容                                                   |
|---------------------------------+------------------------------------------------------------|
| 空バッファへの挿入              | ~insert(0, "hello")~ → ~len_chars() == 5~                  |
| 中間挿入                        | ~"helo"~ の offset 3 に ~"l"~ 挿入 → ~"hello"~             |
| 削除                            | offset 0 の 1 文字削除 → 残り文字列が正しい                |
| 行番号変換                      | 3 行テキストの行 1 → char_offset が正しい                  |
| Unicode 境界（日本語・絵文字）  | 日本語・絵文字を含む文字列でのオフセット計算が正しい       |
| 大規模データ（100,000 行）      | ~insert~ が panic せず完了する（O(log N) の健全性確認）    |

** 5.2. editor/history.rs 新設時（Undo/Redo）

| テストケース              | 確認内容                                     |
|---------------------------+----------------------------------------------|
| ~undo~ 1 回               | 挿入 → undo → バッファが元に戻る             |
| ~redo~                    | undo → redo → 挿入状態に戻る                 |
| ~undo~ スタック空         | undo を余分に呼んでも panic しない           |
| ~undo/redo~ の冪等性      | proptest で任意の操作列で crash しない       |

** 5.3. renderer/text.rs 新設時（cosmic-text 統合）

テキストレイアウト計算の結果（グリフの XY 座標）を数値アサートするテストを追加する。
GPU 描画は行わず、~cosmic-text~ の ~Buffer::layout_runs()~ が返す座標値のみを検証する。

| テストケース                   | 確認内容                                              |
|--------------------------------+-------------------------------------------------------|
| ASCII 1 行のレイアウト         | 各グリフの x 座標が monospace グリッドに従う          |
| 日本語混在行のレイアウト       | 全角文字が 2 倍の幅を占める                           |
| Word Wrap 折り返し             | 折り返し後の物理行数が期待通り                        |
| IME プレエディット文字の一時描画 | Commit 後にプレエディット文字が消える                 |

レベル2（スナップショット）テストの追加手順（cosmic-text 統合後）：

# Cargo.toml への追加
[features]

* 7. CI 統合方針

~AGENTS.md~ の規定に従い、~just ci~ （= ~check + lint + fmt-check + test~）の
~cargo test~ ステップで全レベル1テストが自動実行される。

レベル2テストは ~cargo test --features headless-test~ として分離し、
通常の ~just ci~ には含めない（ローカル環境でのGPU依存を避けるため）。

#+BEGIN_SRC plaintext
just ci                              ← 常時実行（レベル1のみ）
cargo test --features headless-test  ← CI 専用ジョブ（レベル2、cosmic-text 導入後）
#+END_SRC
